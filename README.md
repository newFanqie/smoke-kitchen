# 烟火厨房 · Smoke Kitchen

Minecraft Java **26.1.2 / Fabric** 的世界内做饭模组。通过砧板切配、锅具投料、调火和翻炒，把食材做成可以装盘分享的饭菜。

**当前版本：0.1.11 开发版。** 新增4盐晶的小批盐罐，实际只有4次用量；16盐晶满罐路线保留。原版与实际启用Iris完成基础原料起步的合成、杀鸭取肉、小火炼油、切配炖汤、装碗食用和保存重开。按用户确认，测试可以提供基础材料及生成动物，制作与烹饪须实际操作；自然跑图未完成且不再作为发布门槛。完整设计仍有独立生物美术、建筑、经营及设备功能等明确待办。本版完成后按用户要求暂停续做，等用户说继续再恢复。见 [实现状态](docs/IMPLEMENTATION-STATUS.md)、[有限待办](docs/WORK-QUEUE.md) 和 [玩法设计](docs/DESIGN.md)。

## 当前玩法

- 在世界中切菜、投料、加水、调味、翻炒、装盘和搬锅。
- 食材分别计算熟度；锅具有余热，过热和疏于翻炒会烧焦。
- 陶锅、汤锅、炒锅、平底锅、蒸笼、烤盘、烤炉与两个独立灶眼的双眼灶。
- 29 道命名菜、通用菜肴、17 种作物、研磨压榨与发酵腌制。
- 基础生物、盐矿与 9 类探索建筑的生成框架。
- 冰柜、可关闭的保鲜、翻页食谱、中文提示和世界内食材显示。
- 独立的“烟火厨房”创造分类、7 种刷怪蛋、5 种熟肉/水产与熔炉/烟熏炉配方。
- 天然气开采机、储气罐、燃气管道与气灶；有限气源、断气停火、气罐搬运。

## 第一顿饭

1. 用黏土和圆石制作泥灶、陶锅、砧板和石厨刀。煤、木炭、木棍和谷壳可作燃料。
2. 持锅右键灶台，锅会嵌入灶面。持煤点击侧面自动点火；空手点侧面调火，点顶部投料。
3. 河流、沼泽岸边采野生稻谷，留种在根旁两格内有水的耕地扩种；收获的稻谷在手磨脱壳得到米与谷壳。其余种子的提示写明来源，草丛也按地区掉种子。手磨加入材料后，空手右键操作。
4. 陶锅先用水壶加入1–3份水，再放一份米；煮沸后空手点灶台侧面转小火，加盖至少焖10秒并熟透，再持碗或盘右键盛出两碗饭。准星提示会显示小／中／大火。
5. 葱先在砧板切块或剁碎。炒锅加油、预热到110°C后下蛋，至少四成熟再倒入两份米饭，最后下葱、加盐；最后投料后翻炒至少3次，熟透装盘。倒米饭时返还原来的碗。
6. 拿着厨师食谱右键，可翻页查看教程与菜谱。

普通右键投一份原料；潜行空手点锅具顶部取回单份食材，煮熟的原版鸡肉会变为真正的熟鸡肉。碗盘右键按菜谱分餐。砧板右键切四次，潜行持刀切换切法。锅具顶部空手切换支持的做法，灶台侧面空手调火。潜行持隔热布右键可搬运整锅，保留熟度、水、盖子和做法。煮、蒸、炖都需要水；蒸菜需加盖，空手点顶部可开盖取回盖子。加水会降温，水烧干可能烧焦；最后加入的生肉仍要独立煮熟。

煎、烤时用夹子、锅铲或长筷翻面，一面凝固后再翻，另一面继续受热。白粥等软烂菜显示自己的进度；未软烂时提前持碗不会消耗碗。锅与砧板上的悬浮字已移除，潜行看设备可查看内容与剩余菜品。红烧肉先用无水油糖锅炒出糖色，再下肉加水；别把糖一直烧到黑色。每道菜的切法、用量和阶段要求以食谱书为准。

盐矿研磨成盐晶，16 份盐晶与空罐制成满罐，4 份盐晶与空罐可装4次用量。使用中图标统一显示50%，实际余量精确保留。油菜籽与玻璃瓶在压榨机中制油；早期可把普通猪掉的动物脂放冷陶锅或平底锅用小火熬透，空罐收猪油并回收油渣，不需要红石压榨机。发酵和腌制加入材料后，空手右键密封。数值与操作会随开发继续调整。

## 天然气厨房

在新生成的区块地下 **0–48 层** 找到含气岩层，将开采机放在紧邻岩层的位置。用燃气管道连接开采机、储气罐和天然气灶，持锅右键嵌入气灶。空手点侧面切换关火/小火/中火/大火，正在燃烧时灶面有原版蓝色火焰动画并发光。也可把有气的便携罐直接接在气灶上；潜行空手点侧面拆罐。

岩层初始 2400 单位气，开采机会转移气量，不会无限生成。开采机和储气罐可用空燃气罐取出最多 600 单位气，也可用有气的罐补气。气罐只有满100%、使用中50%代表图标、空0%三个物品；实际余量通过提示和存档精确保留。管路检查只访问已加载的连接节点，最多 64 个；空气不再耗尽搜索预算。断开后，灶内余气用尽即停止供热。

设备保持立体方块模型；刀、铲、勺、夹子等工具直接继承原版模型，避免模糊雷同的细小体素图标。炉身封闭，燃烧面、火焰、烟雾和声音引用原版。全部 309 个物品及状态集中在“烟火厨房”创造分类，首次打开自动选中。运行时引用游戏内置素材，不捆绑原版贴图文件。原版及 Iris 实测组合和限制见本次更新说明。

## 构建与验证

需要 **JDK 25**。Windows 使用：

```powershell
.\gradlew.bat build runGametest
```

Linux/macOS 使用：

```sh
./gradlew build runGametest
```

输出在 `build/libs/`。单元测试位于 `src/test/`，真实游戏测试位于独立的 `src/gametest/`，测试模组不打包进正式 JAR。

可运行 `./gradlew runClienttest` 用实际客户端检查全部物品图标和灶台画面，截图位于 `build/clienttest/screenshots/`。该检查需要图形环境和首次下载官方资源，客户端测试代码不会打包进正式模组。

内容由 `tools/generate-content.mjs` 维护，使用 Node.js 重新生成并检查：

```sh
node tools/generate-content.mjs
node tools/validate-content.mjs
```

配置位于游戏实例的 `config/smoke-kitchen.json`。`spoilage` 控制变质，`freshDays` 和 `spoiledDays` 控制品质下降与不可食用的游戏日数。存档关闭不按现实时间补算，持续运行的服务器按游戏时间推进。`burns`默认false，开启后徒手接触热锅受伤；`detailedHints`默认true，关闭后不再自动显示准星详情和投料建议，温度计、食谱、品质物品提示和直接操作反馈仍可使用。配置修改后重启游戏或服务器。

[第一餐获取路线核对](docs/FIRST-MEAL-ROUTE.md)列出了米、盐、油和工具的依赖；当前验收按用户确认提供基础材料，合成与做菜实际执行，自然采集历史另存记录。
